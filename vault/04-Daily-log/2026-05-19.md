## What I learned (or confirmed)

- `pd.Series.rank(pct=True, ascending=...)` is the cleanest primitive — `ascending=False` makes "lower is better" rank correctly without `100 - pct` arithmetic
- `df.groupby(...).transform(lambda s: s.rank(...))` keeps row alignment, so per-sector ranks slot straight back onto the original frame without merges
- `df.mul(series, axis=1).sum(axis=1)` over `notna()` mask is a clean way to renormalize a weighted mean when components are missing per-row
- yfinance returns `None` for `dividendYield` on the two EU accumulating ETFs (EQQQ.DE, VWCE.DE) — they got composite from momentum only. Not a bug — distributing ETFs would return a real value
- Visible "value trap" effect in the smoke test: VOD.L composite 75 because it's strongest in its 3-stock sector on Value and Yield, despite mediocre Quality (33). Sector-relative ranking works as intended
- Negative-P/E / negative-P/B / negative-D/E are real cases (loss-makers, write-downs, negative-equity firms) — sanitized to NaN upfront so they don't dominate the "low is better" ranks

## Sanitization rules used in score.py

- `trailing_pe <= 0` → NaN (negative earnings)
- `price_to_book <= 0` → NaN (negative book value)
- `debt_to_equity < 0` → NaN (negative equity)
- Drop rows with fewer than 4 of the 7 core metrics present

### What I learned

- `feedparser.parse(url, agent=USER_AGENT)` — always pass a UA, some feeds reject default
- `parsed.entries` empty + `parsed.bozo_exception` present = parse failed; either may be true alone. Log and skip
- yfinance `.news` schema has TWO shapes in the wild — defend against both with `if isinstance(item.get("content"), dict)`

- Sort-by-date across mixed feeds means the most prolific feed dominates the top-N. Round-robin per-source could balance it; revisit only if narrate.py output ends up skewed toward one source

### Decisions made

- **Don't dedupe within the same feed** (assume the feed itself doesn't repeat). Dedupe is only across feeds via case-folded title — same wire story syndicated to multiple outlets shows once

## Session 3 (same day) — narrate.py

### What I did

- Designed the pick payload to include not just raw metrics + percentiles, but also **sector medians** so Claude can write comparative phrases like "8.5x vs sector median 22x" without inventing numbers
- Implemented `narrate_pick(client, pick, headlines)` and `narrate_macro(client, headlines)` — both with `cache_control: {"type": "ephemeral"}` on the system prompt
- Two distinct system prompts: one analyst persona for picks, one macro/geopolitics persona for the daily paragraph
- Set up local `.env` (copied from `.env.example`, dropped in fresh Anthropic key)
- Smoke-tested both functions on real data: VOD.L pick + 12 macro headlines
- Output groundedness verified — every number in the VOD.L narration traced back to the payload (no hallucinated metrics); macro paragraph names only real headlines from today's BBC/CNBC/FT/Handelsblatt pull

### What I learned

- **Anthropic API key hygiene**: pasting a secret into a Claude Code chat stores it in `.claude/projects/*/*.jsonl` session logs in plain text. Generate-once-paste-once-into-.env is the right pattern; never paste a secret into chat. (See [[reference-credentials]])
- **Sector medians are the unlock for comparative narration** — without them, Claude says "trades at low P/E"; with them, it says "8.5x vs sector median 22x". Same model, qualitatively different output, just from richer structured input
- `.env.example` is the committed template; `.env` is the gitignored real file. Convention worth internalizing for any project that uses secrets
- Pick narrative ran slightly over the 80-word soft limit (~95 words) — the extra length came from Claude listing more comparative numbers than expected. Tradeoff: tightening would lose data anchors. Leaving for now
- Macro narration was crisp at ~120 words. Format spec adherence was perfect (no tickers, no predictions, specific actors named)

### Decisions made

- **Pass sector medians to Claude per pick.** Without them, narration can't compare; with them, it does so accurately. Computing the medians is a one-liner over the fundamentals frame in `main.py`
- **Use ephemeral cache on system prompt** even though daily runs are short — costs nothing extra, and saves on input tokens for ~10 picks in the same 5-minute window
- **Separate macro prompt** rather than reusing the pick prompt — different persona, different format. Cleaner than overloading one system prompt

## Session 4 (same day) — main.py + synthesis + end-to-end run

### What I did

- Added `narrate_synthesis(client, picks, composition, macro_blurb, universe_meta)` — a third Claude call after pick + macro narration. Persona: chief equity strategist (think Druckenmiller, not CNBC). Output: 3 paragraphs covering dominant factor / connecting threads / outlier + absence + catalysts
- Added a "Strategist's read" section to `dashboard.html.j2` between hero and macro, with a gold-accent CSS treatment that visually anchors it as the headline view
- Implemented `archive.py::save_daily` — JSON snapshot at `archive/YYYY-MM-DD.json` covering picks, narratives, macro, synthesis, composition, universe meta
- Implemented `render.py::render_dashboard` — Jinja2 rendering with format helpers for percentages, ratios, prices, sector → exchange mapping (`.L` → LSE, `.DE` → Xetra, etc.), and tone classes for positive/negative metric coloring
- Implemented `main.py` orchestrator with `--limit N` argparse flag for fast local iteration. Full pipeline: universe → data → score → sector medians → headlines → narrate (pick × N + macro + synthesis) → archive → render
- First end-to-end run on `--limit 100` succeeded (3 cached + 97 fresh fundamental fetches, 99 stocks ranked, 12 Anthropic API calls total)
- **Bug caught in first run**: per-pick narratives came back saying "metrics came through empty". The synthesis worked because it explicitly reads `raw_metrics` / `scores`, but `narrate_pick._build_pick_payload` was reading the old keys `metrics` / `percentiles` from the standalone smoke test. Fixed by making it fall back gracefully to both naming conventions
- Second run produced sharp, grounded narration on every pick AND a strategist-quality synthesis

### What I learned

- **Naming consistency across module boundaries is load-bearing.** A typo-level mismatch (`raw_metrics` vs `metrics`) silently degraded narration without erroring — Claude just (correctly) refused to invent numbers and flagged the absence. Easy to miss without an end-to-end run
- **Three-tier narration (pick / macro / synthesis) compounds.** The synthesis pulls together what individual picks see in isolation. A line like "the screen is buying what AI isn't" cannot come from any single pick narrative — only from cross-pick pattern detection. Worth every cent of the 12th API call
- The strategist persona + structured composition stats (`avg_component_scores`, `region_breakdown`, `missing_sectors`) produces noticeably better synthesis than the same picks without those aggregates. Composition stats are cheap to compute and qualitatively change the output
- `argparse --limit` is the right escape hatch for local iteration. Full universe is fine for cron; `--limit 100` is a 3-5 minute round trip for human-in-the-loop development
- The fundamentals cache means the second same-day `--limit` run is fast — only the LLM calls re-run. Useful for iterating on prompts

### Decisions made

- **Composition stats live in `main.py`, not `score.py`.** They're a presentation/synthesis concern, not a scoring concern. Keeps the scoring module purely numerical
- **Sector medians live in `main.py` too** — single `_sector_medians(fundamentals)` helper that runs once and gets handed to every pick. Could promote to a separate module if it grows; one-liner today
- **ETF narration deferred to mechanical text for now** — `score_etfs` doesn't produce enough fundamentals to merit a Claude call per ETF. Current behavior: a one-line auto-generated summary ("Ranked on momentum + yield · 3M return X% · yield rank Y/100"). Revisit if real users want richer ETF prose
- **Hero headline auto-derived from composition** — if a single sector dominates the picks, the H1 reads "Healthcare leads today's screen". Otherwise generic. Cheap and dynamic
- **Synthesis section visual treatment**: gold accent (`--warn` color from the palette) for a deliberate "this is the headline view" feel. Distinct from the macro section's purple accent
